# ADR-0007: Apache-2.0, and what it forbids us from depending on

- **Status:** Accepted
- **Date:** 2026-08-29
- **Phase:** 0 — governs every dependency choice

## Context

The project will be open source long term. Commercial use is not a personal goal, but **open
source is not the same as non-commercial**, and you cannot grant rights you do not hold.

## Decision

**Apache-2.0.**

The operative consequence is on dependencies, not on the license file:

- **CC-BY-NC models and datasets are disqualified.** Shipping an Apache-2.0 project that only
  works with a non-commercial model either poisons the license or forces the model to be
  optional-and-not-default.
- **No ESV text anywhere in the repo.** Not in fixtures, not in test data, and specifically not in
  the eval golden set — the likeliest place it sneaks in, since golden sets naturally contain
  expected passages. Crossway's terms also bar ESV text from anything published under a Creative
  Commons license, which is live if docs or datasets are CC-licensed.
- **Per-chunk `license` and `attribution` metadata** so the attribution page generates
  mechanically and the verification layer can refuse to serve anything unlicensed — the same
  mechanism already built for tier checking.

## Alternatives rejected

- **MIT.** Apache-2.0 carries an explicit patent grant that MIT lacks, which matters more in AI
  tooling.
- **AGPL.** Would only prevent a closed hosted fork, which is not worth the contributor friction
  given the goals here.

## Consequences

Personal non-commercial intent does not rescue a restrictively licensed dependency. Every model,
dataset, and corpus addition needs a license check as part of review, not after.
